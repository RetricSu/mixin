# 密信

一个给普通人用的桌面安全传递工具。打开后只需要选择“发送”或“接收”，不必理解密码学术语。

## 产品方案（MVP）

- **发送文字**：输入内容，选择约定口令或联系人身份，生成可复制的密信。
- **发送文本文件**：选择 `.txt`、`.md`、`.csv`、`.json`、`.log`，文件内容与文件名、扩展名、类型一起封装后加密。
- **联系人身份**：首次打开自动生成本机身份。公开身份可复制或展示二维码；私密身份仅保存在本机。
- **接收**：粘贴密信。文字直接显示，文件会要求选择保存位置并恢复原文件名和扩展名。

“约定一个口令”适合双方已经有安全沟通渠道的场景；“发给一位联系人”适合长期联系人，不需要每次重新约定口令。二维码当前用于展示和传递公开身份，扫码结果可以粘贴到发送框；摄像头扫码属于后续迭代。

## 安全边界

- 口令路径使用 AES-256-GCM，并为每次加密随机生成 nonce。
- 联系人路径使用 RSA-OAEP-SHA256 包住随机会话密钥，再用 AES-256-GCM 加密实际文字或文件，因此不受 RSA 小载荷限制。
- 私密身份文件写入操作系统应用数据目录，并在 Unix 系统设置为仅当前用户可读写。
- 密文和口令必须分开传递。弱口令、丢失私密身份或在不可信机器上运行，仍会导致风险。

## 编译

```sh
cargo test
cargo build --release
```

跨平台打包仍可使用 `build.sh`，但目标环境需要对应的 Rust target 和 Windows 交叉编译器。
